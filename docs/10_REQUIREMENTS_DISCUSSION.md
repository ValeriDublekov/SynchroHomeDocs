# Въпроси за Дискусия, Архитектурни Компромиси и Решения
## Документ: 10_REQUIREMENTS_DISCUSSION.md

Този документ съдържа теми за обсъждане, открити въпроси и архитектурни компромиси (Architectural Decision Records - ADRs), които изискват валидация преди старта на финалното кодиране.

---

### Тема 1: Cloudflare Access срещу Мобилното Android Приложение
- **Статус**: **РЕШЕНО (Одобрен Вариант А - Двуслоен модел)**.
- **Архитектурно решение**:
  - Web UI (`https://reminders.yourdomain.com/`) се предпазва от **Cloudflare Zero Trust (Google Login)** на ниво Edge.
  - API маршрутите (`/api/*`) пропускат заявките през криптирания тунел и се валидират на ниво **.NET 9 API чрез Google JWT Bearer Token**.
  - Мобилното Android приложение не съхранява чувствителни Cloudflare Service Credentials.

---

### Тема 2: Google Calendar — Пълен REST API или Лесен iCal Линк?

- **Контекст**: Споменахте, че показването в Google Calendar е опционално.
- **Варианти за избор**:
  - **Вариант 1 (iCal / ICS Линк)**:
    - Сървърът генерира URL като: `https://reminders.yourdomain.com/api/calendar/feed.ics?token=xyz`.
    - Добавя се в Google Calendar за 30 секунди.
    - *Минус*: Google опреснява външни календари бавно (веднъж на 8-24 часа).
  - **Вариант 2 (Google Calendar API v3)**:
    - Реално време: щом маркирате "Изпълнено" на телефона, събитието в календара веднага се премества/маркира със зелен цвят `[✓ Готово]`.
    - *Минус*: Изисква еднократно създаване на проект и OAuth Client ID в Google Cloud Console.
- **Въпрос към вас**: Имате ли готовност за настройка на Google Cloud Console за двупосочен Calendar API, или предпочитате старт с iCal?

### Тема 3: Персонализирани Звуци (Custom Sounds) на Телефона

- **Контекст**: Искате custom звуков сигнал за напомнянията.
- **Android специфика**: В съвременния Android Notification Channels изискват звукът да е предварително дефиниран в системните ресурси на приложението (`res/raw/`) при създаването на канала.
- **Препоръка**:
  - Вграждаме пакет от 6-8 висококачествени звуци (Медицински алармен тон, Камбанка за уреди, Фин сутрешен гонг, Сирена за спешни задачи и др.) директно в Android APK файла.
  - През Web UI вие просто избирате от падащо меню кой звук да се прикачи към всяко правило.

### Тема 4: Запазване на часа при плаващо изчисление (From Completion)

- **Контекст**:
  - Пример: Лекарство на всеки 3 дни в 08:00 сутринта. Потребителят закъснява и го изпива в 14:30.
- **Препоръчано решение**:
  - При `FromCompletion` следващата дата запазва първоначалния час `target_time` (08:00), за да не се измества регулярният сутрешен режим.

---

### Тема 5: Синхронизация между Няколко Устройства

- При маркиране като "Изпълнено" на едно устройство (телефон), сървърът изпраща FCM Data/Silent Push към останалите активни устройства на потребителя (таблет), за да анулира локалната нотификация в системната лента.

### Тема 6: Валидирани Решения от Обратната Връзка (ADR Резюме)

| Функционалност | Решение на потребителя | Архитектурно отражение |
|---|---|---|
| **Тихи часове (Quiet Hours)** | ❌ Пропуска се за v1 | Разчита се на стандартния "Не безпокойте" (DND) режим на Android OS. |
| **Предсрочно изпълнение (Complete Early)** | ✅ **Одобрено** | Добавено поле `is_early_completion` в `reminder_instances`, ендпойнт `/api/instances/{id}/complete-early` и бутон в UI. |
| **Локален Wi-Fi порт (LAN Fallback)** | ❌ Отхвърлено | Запазва се строга изолация: 0 отворени порта на рутера/хоста, само Cloudflare тунел. |
| **Лекарства с 2–3 приема дневно** | ✅ **Одобрено** | Поле `target_times TIME[]` в `recurrence_rules` за автоматично превъртане на следващия прием в рамките на едно правило. |
| **Cloudflare сигурност (Тема 1)** | ✅ **Одобрен Двуслоен модел** | Cloudflare Zero Trust пред Web + Google JWT Bearer Token за `/api/*`. |
| **Чеклист / Action Subtasks** | ❌ Пропуска се за v1 | Обикновеното поле `description TEXT` е напълно достатъчно. |
| **Интелигентно бързо отлагане (Smart Quick Snooze)** | ✅ **Одобрено** | Преки бутони в Android известието: `[+1 час]` и `[Довечера 20:00]` / `[Утре 09:00]`. |
| **Брояч на консумативи / Наличности** | ❌ Пропуска се за v1 | Оставя се за бъдеща версия при необходимост. |
| **История и статистика на изпълнението** | ✅ **Одобрено** | Нов ендпойнт `/api/stats/compliance` + графичен модул в Web таблото за средно закъснение и редовност. |
| **Еднократен резервен архив с 1 клик** | ✅ **Одобрено** | Ендпойнти `/api/backup/export` и `/api/backup/import` за мигновено сваляне/качване на пълен JSON архив. |
